# Fieldcast Invoice Desk

Fieldcast Invoice Desk is a small invoice intake workflow: **upload PDF → extract fields → run validation rules → approve, reject or correct in a review queue → export Excel/JSON**. A SQLite audit log records every step.
It was built for the lablab.ai *Vultr: Agent Rush* hackathon (Challenge 2 – Finance & Accounting) and is MIT licensed.

## What it does (implemented)
- **Extraction** (`invoice_desk/extract.py`)
  - Reads the PDF text layer with pdfplumber. If the page has almost no text (a scan), it falls back to OCR with Tesseract (`pytesseract`; the Docker image includes it).
  - A **rule-based parser** extracts invoice number, date, seller, buyer, currency, subtotal, tax, total and line items. It needs no API key.
  - **Optional LLM:** if `LLM_BASE_URL`, `LLM_MODEL` and `LLM_API_KEY` are set in `.env`, an OpenAI-compatible endpoint fills or overrides fields (temperature 0, `null` if absent). If the call fails, the app falls back to the rules.
- **Validation rules** (`invoice_desk/rules.py`). Each rule returns pass/fail and a human-readable explanation:
  - `required_fields`: invoice_number, invoice_date, seller, total
  - `line_items_sum`: sum of line amounts = subtotal (± tolerance)
  - `subtotal_plus_tax`: subtotal + tax = total (± tolerance, default 0.02)
  - `duplicate_number`: invoice number already in the desk (rejected ones excluded)
  - `valid_date`: date missing, unparseable or in the future
  - `amount_threshold`: total above `AMOUNT_THRESHOLD` (default 10000)
- **Review queue** (`invoice_desk/db.py`)
  - Invoices that pass every check are auto-approved; anything else is set to `in_review`.
  - A reviewer can **approve**, **reject** (a reason is required) or **correct** fields. Correcting re-runs the checks.
  - Every action is written to the `audit` table with actor, note and UTC time.
- **Web UI** (Flask + Jinja): multi-file upload, a list with status badges, a detail page (fields, checks, line items, audit log) with approve/reject/correct, and Excel (Invoices + Line items sheets) or JSON download (`?status=approved` filter).
- **Health:** `GET /health`.

## Architecture
```
Browser ─► (port 80) gunicorn/Flask container on a Vultr Cloud Compute VM
              ├─ extract:  pdfplumber ─► (scan?) Tesseract OCR ─► rule parser ─► optional LLM (.env)
              ├─ rules:    6 checks with explanations
              ├─ queue:    approved | in_review | rejected  + audit log
              └─ export:   XLSX / JSON
           SQLite + uploaded files in the docker volume `desk-data` (/data)
```
**Vultr usage:** the whole backend (API, UI, queue, database) runs on one Vultr Cloud Compute VM. An LLM is optional; Vultr Serverless Inference (`https://api.vultrinference.com/v1`, OpenAI-compatible) can be set as `LLM_BASE_URL`, but this has **not been tested** yet.

## Run
**Docker (recommended, e.g. Vultr Ubuntu VM with Docker installed):**
```bash
git clone <repo-url> fieldcast-invoice-desk && cd fieldcast-invoice-desk
docker compose up -d --build        # → http://<server-ip>/
```
An `.env` file is optional (`cp .env.example .env` to set LLM or thresholds). **Never commit `.env`.**

**Without Docker (Ubuntu, as root):** `./install.sh` installs the Python venv, Tesseract, a systemd service and an nginx proxy.

**Local dev:**
```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m invoice_desk.app      # http://127.0.0.1:8010
.venv/bin/python -m pytest -q             # 12 tests
```

## Sample invoices (`samples/`)
- `sliced-invoice-INV-3337.pdf`: the public demo invoice from Sliced Invoices. All checks pass.
- `acme-invoice-1001.pdf`: a **synthetic** invoice with fictional companies, generated by `scripts/make_samples.py`. All checks pass.
- `acme-invoice-1002-bad-total.pdf`: synthetic, with a **deliberately wrong total** (250.00 instead of 185.88). It goes to review.

## Known limits
- The rule-based parser targets common English invoice layouts ("Invoice Number", "Sub Total", "Tax", "Total", one line per item). Other layouts may give `null` fields, which then show up as failed checks. That is safe, but it means more manual review. The LLM option improves this.
- OCR has only been exercised for import; no scanned invoice has been tested end-to-end yet.
- No login or user accounts. The reviewer name is free text, so put the demo behind a private URL or add auth before real use.
- Single-currency checks; no tax-rate validation or bank/ERP reconciliation.
- Tested on the 3 sample PDFs above only; not tested with real customer documents.
